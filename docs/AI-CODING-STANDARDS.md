# AI 编程规范

本项目允许使用 AI 辅助设计、编码、测试、文档和代码审查，但 AI 生成的内容
必须由贡献者负责验证。仓库根目录的 `AGENTS.md` 是可执行约束；本文是面向
维护者和开源贡献者的说明。

## 变更原则

AI 先读后改，先判断模块边界，再修改最小范围。任何跨模块修改都要说明依赖
方向和回滚方式。不能为了让示例“跑起来”而绕过权限、审批、租户隔离或审计。

AI 不得执行以下行为：

- 伪造测试、构建、部署或安全扫描结果。
- 读取、输出或提交密钥、生产数据和个人敏感信息。
- 自动升级依赖而不更新版本矩阵。
- 把 Spring AI、供应商 SDK 或数据库实体泄露到领域层。
- 让 Python、前端或模型直接写任务状态或业务系统。
- 未经确认删除、重置、覆盖或迁移用户文件。

## AI 生成代码的审查清单

提交前至少检查：

- 是否保留了 `tenantId`、`userId`、`traceId` 和审计上下文。
- 是否将模型输出重新交给 Policy Engine，而不是直接执行 Tool Call。
- 写操作是否有风险等级、权限、审批、幂等键、超时和重试上限。
- 是否覆盖了错误路径、终态、超时、重复消息和权限拒绝。
- 是否同步修改了 OpenAPI、JSON Schema、A2A/MCP 文档和示例。
- 是否新增了真实地址、密钥、日志中的敏感内容或不必要的依赖。
- 是否在本地运行了可用的测试；无法运行时是否明确记录原因。

## 推荐提示词结构

向 AI 分配任务时，提供：

1. 目标模块和允许修改的目录。
2. 当前业务不变量和不可突破的安全边界。
3. 输入输出契约和错误行为。
4. 测试命令和验收标准。
5. 是否允许改变数据库、协议或依赖版本。

示例：

```text
在 java-platform/policy-engine 内实现一个纯 Java 审批规则。
不得引入 Spring；高风险写工具必须返回 requiresApproval=true；
缺少 write 角色或幂等键必须拒绝；增加正向和负向 JUnit 测试。
```

## 责任归属

AI 贡献必须由提交者审阅。提交者应能解释每一处行为变化，并为引入的依赖、
协议变更和数据迁移承担维护责任。
